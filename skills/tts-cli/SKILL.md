# Generate audio with ttsi

- Install with `go install github.com/smkod/tts-cli/cmd/ttsi@<release>` once a release is available, or `go install ./cmd/ttsi` from a checkout. Use Go 1.26 or later. Enable Google Cloud Text-to-Speech and configure Application Default Credentials. Do not put secrets in the YAML file.
- Before using the CLI, run `ttsi agent-guide` (or `ttsi agent-guide --json` and read `data.instructions`). Follow the bundled guide for discovery, generation, batch recovery and safety; it matches the installed executable and needs no external documentation.
- Use `--json` for operational commands and read the returned absolute file paths rather than guessing them. Only pass successful, non-preview audio files to downstream tools.

## Optional AnkiConnect workflow

1. Read only the target notes with AnkiConnect (`notesInfo` after resolving note IDs). Identify the intended text and audio fields. Skip notes with existing audio unless replacement was explicitly requested.
2. Generate audio for the missing fields using note IDs as batch IDs. Continue only for successful items with a real file.
3. Upload with `storeMediaFile`, specifying `deleteExisting: false`. Use the absolute path if Anki and the CLI share a filesystem; otherwise send the generated bytes as base64. Use the filename returned by AnkiConnect.
4. Re-read the target field before writing. If it now contains audio and replacement was not requested, leave it alone. Preserve existing field content and add `[sound:<returned-filename>]` using `updateNoteFields` with only that field.
5. Re-read the updated notes and verify the sound reference and media file. Do not change unrelated notes, fields, tags, or decks.
